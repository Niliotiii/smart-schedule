# Implementation Plan: Dashboard Signal Access

**Branch**: `017-dashboard-signal-access` | **Date**: 2026-05-18 | **Spec**: [spec.md](/specs/017-dashboard-signal-access/spec.md)
**Input**: Feature specification from `/specs/017-dashboard-signal-access/spec.md`

## Summary

Move the "Sinalizar" button from the schedules/months index page row actions to a quick-access card on the Dashboard. Create a consolidated signal page that shows schedules from ALL months with status "disponivel" so users can signal availability for everything in one place.

## Technical Context

**Language/Version**: TypeScript, Node.js 20+  
**Primary Dependencies**: AdonisJS 6, Lucid ORM, Inertia.js (Vue 3), PrimeVue  
**Storage**: PostgreSQL  
**Testing**: N/A (UI-level change, no new business logic)  
**Target Platform**: Web (responsive, desktop + mobile)  
**Project Type**: Monolithic web app (AdonisJS backend + Inertia Vue frontend)  
**Performance Goals**: Page load under 1s (small data — at most 12 months × 31 schedules)  
**Constraints**: Must reuse existing signal endpoints (`POST /schedules/:scheduleId/signal`)  
**Scale/Scope**: 1–12 months in "disponivel" status, < 50 schedules total
